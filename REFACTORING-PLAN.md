# RDFa Editor: generalize, DRY, fix RDFa semantics

## Context

The `xslt3-annotation-editor` branch (commit 7e91122) upgraded the prototype to XSLT 3.0 + SaxonJS 3 (IXSL) and added an annotation overlay (property/entity/advanced patterns), edit mode, and an XSLT 3.0 RDFa→RDF/XML extractor. Review found the architecture sound but the implementation prototype-grade. Goal: bring the editor close to usable state — generalize, DRY, cover realistic RDFa edge cases — while keeping the XSLT 3.0 + IXSL architecture and staying aligned with the LinkedDataHub v6 document format.

**Bugs to fix**
1. `src/index.xsl:266,272` — form radios read via `@checked` *attribute* predicate, which never changes on user click (only the DOM `checked` property does) → the chosen pattern/value-type is always the markup default; Entity/Advanced patterns and custom values never apply on create.
2. `src/RDFa2RDFXML-v3.xsl` — `@property`+`@typeof` without `@about` mishandled: per RDFa 1.1 the new typed node must become the **object** of `@property` (chaining), children inherit it as subject. Currently the typed node becomes the subject of a literal — exactly the markup "Create Entity" emits, so the editor's own output round-trips wrong.
3. No base-URI resolution: `about=""` (used on every demo paragraph) extracts as `rdf:about=""`; relative URIs/fragments unresolved. Also: blank nodes emitted as `rdf:about="_:…"` — invalid RDF/XML (must be `rdf:nodeID`).
4. `src/index.xsl:578` — second overlay copy's `<form>` lacks `id="annotation-form"` → form reset no-ops.
5. Language: only `@xml:lang` checked; browser DOM has `@lang`. No inheritance.
6. Click-to-edit on `span[@property]` conflicts with contenteditable caret placement.

**Duplication to eliminate**: overlay form markup ×2 (~120 lines each), red-flash block ×2, pattern→attribute application ×2 (edit/create), fieldset-visibility logic ×2, vocab option lists hardcoded ×2. Dead code: `subject-context` accumulator, `contextElement`/`commonAncestor`, `editMode` boolean (derivable from `editingSpan`), unwired "-- Custom property --" option, `window.Function` string-eval hack for flash removal.

**User decisions (fixed)**
- Edit UX: **unified right-click** — one `oncontextmenu` dispatcher: target inside existing annotation → edit mode pre-filled; else validate selection → create mode. Remove the `span[@property]` onclick handler.
- Overlay UI: **generated by XSLT** once at startup from a single named template, hidden; handlers only populate/show/hide.
- Vocab config: **RDF/XML ontology files only** (no custom manifest format); dropdowns populate generically; vocab list = stylesheet param of document hrefs.
- Extractor scope: bug fixes + `@vocab`/bare-term resolution (RDFa Lite) + skip `data-role="rendering"` subtrees. Keep `@prefix`/CURIE consumption. **Out of scope (document as future work)**: `@rel`/`@rev`, `@inlist`, safe CURIEs, `@datetime`/`<time>`, `xml:base`.

## LinkedDataHub v6 alignment

Contract from `/Users/martynas/.claude/plans/how-would-you-suggest-parsed-cake.md` and `"/Users/martynas/WebRoot/LinkedDataHub Design System/templates/v6-northwind-products.xhtml"` (LDH v6 plan anticipates "Phase D: RDFa-Editor integration"):
- **Absolute URIs always** in `@about`/`@typeof`/`@property`/`@resource` (predicate = `namespace-uri() || local-name()`); no CURIEs/`@vocab`/`@prefix` in *emitted* markup (the editor already does this — keep).
- `@about=""` = the document; `#fragment` = document part; absolute URI = external resource. Containment via `property="https://schema.org/hasPart"` on nested blocks.
- Hidden definitions `<span property resource/>` / `<span property content/>`; hydrated output inside `data-role="rendering"` → extractor **skips** those subtrees (including their text when computing enclosing literals).
- No framework classes on content; editor UI chrome keeps its own classes.

> **Decision (user, 2026-07-05): strict W3C conformance — no profile deviations.** Per RDFa 1.1, `@about`+`@property` with no `@content`/`@resource` is a text literal on the `@about` subject. The v6 mockup's `<article about="#frag" property="schema:hasPart">` idiom is non-conformant markup and must change to **object chaining**: `<article property="https://schema.org/hasPart" resource="#frag" [typeof=...]>` — flag for the LDH v6 wiki/mockup. Fixture 09 encodes the conformant idiom.

## Phase 1 — Extractor rewrite (`src/RDFa2RDFXML-v3.xsl`)

Pure XSLT 3.0, entity-free so tests run against `src/` directly. Keep `xpath-default-namespace="http://www.w3.org/1999/xhtml"`. Process from the **root element** (not `//body`) so `@prefix`/`@vocab`/`@lang` on `<html>` are honored; empty skip templates for `head`, `script`, `style`, `*[@data-role='rendering']`.

Context flows top-down as explicit params (drop the dead accumulator):
`$subject as xs:string?`, `$prefixes as map(xs:string,xs:string)`, `$vocab as xs:string?`, `$lang as xs:string?`, `$base as xs:string tunnel`.

Per-element semantics, in order:
1. Context updates: prefixes ⊕ `@prefix` ⊕ `xmlns:*`; `$vocab := (@vocab, $vocab)[1]` (`@vocab=""` resets); `$lang := (@xml:lang, @lang, $lang)[1]` (`''` = no language).
2. New subject: `@about` → resolved; else `@typeof` w/o `@about` → `(@resource,@href,@src)` resolved else deterministic bnode; else bare `@resource|@href|@src` w/o `@property` → that IRI (spec hanging-subject rule); else inherit.
3. `@typeof`: one `rdf:type` per token; subject = typed resource.
4. `@property` per token, object resolution order:
   - `@content` → literal (+`@datatype` typed / `$lang` tagged);
   - else `@resource|@href|@src` → IRI object; **children inherit the object** (chaining);
   - else `@typeof` w/o `@about` → **object = the typed node** (bug-2 fix; `(parent, P, _:b)` + `(_:b, a, T)`);
   - else → plain literal from text content; subject = `@about` if present else inherited (strict RDFa 1.1).
5. Recurse with updated context.

Functions (`rdfa:` namespace):
- `rdfa:resolve-iri($v, $prefixes, $base)` — CURIE only when prefix declared and rest doesn't start `//`; else `resolve-uri($v, $base)` (fixes `about=""` → document URI, `#frag`, relative paths).
- `rdfa:resolve-term-or-curie($v, $prefixes, $vocab, $base)` — absolute IRI as-is; declared CURIE expands; NCName+`$vocab` → concat; NCName w/o vocab → `()` + `xsl:message` warning.
- `rdfa:new-subject($e, …)` and `rdfa:in-scope-subject($e, $base)` (fold over `ancestor-or-self::*`) — **shared with the editor** for the inherited-subject display (replaces the wrong `local:get-inherited-subject`).
- `rdfa:bnode-label($e)` — deterministic sibling-position path (`'b' || join of position indexes`), NOT `generate-id()` (unstable across processors; expected-file tests need reproducible labels).
- `rdfa:split-uri` — keep, guard non-NCName local parts with a warning + skip.

Emission: blank nodes via `rdf:nodeID` (never `rdf:about="_:…"`); one `rdf:Description` per triple in document order (deterministic for diff-based tests; grouping is a cosmetic future step).

Global `<xsl:param name="base-uri" as="xs:string?"/>` declared **only in the extractor** (duplicate declaration via `xsl:include` = static error XTSE0630); `<head><base href>` wins when present; browser passes page URI as a template param; CLI: `base-uri=http://example.org/dir/doc`.

## Phase 3 — Editor refactor

**`src/index.xsl`** (~80 lines): includes the other four; `<xsl:param name="vocab-hrefs" as="xs:string*" select="('vocabs/foaf.rdf','vocabs/dcterms.rdf')"/>`; `local:document-uri()` = fragment-stripped `ixsl:get(ixsl:window(),'location.href')`. `main`: init `editingSpan` to `()`, then `<ixsl:schedule-action document="{string-join($vocab-hrefs,' ')}">` → `local:init-overlay` (async prefetch populates SaxonJS's doc cache; avoids deprecated sync-XHR `document()` at event time and the current first-right-click fetch). Window state: **only** `editingSpan` (edit mode = `exists(...)`) and `range` (create mode). Delete `editMode`, `contextElement`.

**`src/vocab.xsl`** (pure XSLT): generic ontology readers handling both RDF/XML shapes —
- `local:vocab-terms($doc, $kind)`: classes = `owl:Class|rdfs:Class` typed elements or `rdf:type/@rdf:resource` refs; properties = `rdf:Property|owl:ObjectProperty|owl:DatatypeProperty|owl:AnnotationProperty` likewise; require `@rdf:about`; dedupe; if `(//owl:Ontology)[1]/@rdf:about` exists, keep only terms starting with it (kills FOAF's OWL-interop noise).
- `local:term-label($term)`: `(@rdfs:label, rdfs:label[1], URI local-name)[1]`.
- `local:ontology-label($doc, $href)` for optgroup labels: `(@dc:title, dc:title, dct:title, @rdfs:label, rdfs:label)[1]` else `$href`.
- `local:render-term-options($hrefs, $kind)`: one template feeds **both** the typeof and property selects; each ends with `<option value="">-- Custom… --</option>`. All hardcoded schema.org/DC lists and the inline FOAF loop collapse into this.

**`src/overlay.xsl`**:
- `local:render-overlay` — the single copy of the form, `<form id="annotation-form">` (bug 4 by construction), rendered hidden at startup. Add `<input name="custom-property">` (+ `custom-type`) free-text inputs, and a `button.remove-action` (hidden outside edit mode).
- `local:form-values($form) as map(*)` — **bug-1 fix**: all reads via live properties, e.g. `('pattern': ($form//input[@name='pattern'])[ixsl:get(.,'checked')] ! ixsl:get(.,'value'))`; property/typeof fall back to the custom input when select value = `''`.
- `local:populate-form($span?)` — `form.reset()` first; set radios/selects via **properties**; if a URI isn't among the options (`select.value` reads back `''`), route it into the custom input and reveal it (else editing an unknown-property annotation would silently erase it on save).
- `local:update-form-visibility($pattern)` — single fieldset show/hide copy, called from the pattern onchange handler AND `populate-form`.
- `local:show-overlay($event?)` / `local:hide-overlay` — keep the viewport-clamping math verbatim; `hide-overlay` clears `editingSpan`+`range` (single teardown; Cancel = one call).

**`src/annotate.xsl`**:
- Unified dispatcher `match="*[@contenteditable = 'true']" mode="ixsl:oncontextmenu"` (attribute-based pattern — IXSL patterns are re-evaluated per event against target + ancestors, keep them cheap; also generalizes beyond `<p>`). `$annotation := ($target/ancestor-or-self::*[@property or @typeof] intersect descendant::*)[last()]` → edit mode; else guard `rangeCount≥1`/not collapsed, `local:selection-valid($range)` → create, else `local:show-flash($range)`.
- `local:apply-annotation($target, $values)` — the single clear-attrs + pattern-switch copy (replaces both blocks). Drop the `generate-id()` span `@id` (pollutes canonical content).
- Annotate handler (thin): values → editing span or `createElement('span')` + `xsl:try surroundContents` (backstop `xsl:catch` → flash) → apply → hide.
- Remove annotation: unwrap via `insertBefore` each child before the span, `removeChild`, then `parent.normalize()` (merges text nodes for clean caret behavior).
- `local:show-flash($range)` — single copy; removal via `<ixsl:schedule-action wait="1200">` calling a hide template — **deletes the `window.Function` string-eval hack**.
- Extract button: `call-template extract-rdfa` with `$doc = ixsl:page()`, `$base = local:document-uri()`.
- Inherited-subject display uses `rdfa:in-scope-subject()` from the extractor — editor shows the same subject the extractor computes.

### Key gotchas (SaxonJS)

- `checked`/`value`/`disabled` read AND written as properties; `ixsl:set-attribute` only for RDFa attributes that must serialize.
- Overlay markup must be in the XHTML namespace (stylesheet default ns already is) for `ixsl:append-content`.
- `xsl:include` + duplicate global param = XTSE0630 → `$base-uri` lives only in the extractor.
- DTD entities: keep `xmlstarlet c14n` for the editor modules; extractor stays entity-free so tests bypass `build/`.
- `preventDefault` on contextmenu kills the native spellcheck menu inside editable content — accepted trade-off.
